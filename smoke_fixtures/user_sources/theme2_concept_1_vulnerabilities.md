# Конспект 1. Уязвимости: определения, свойства и классификация

## Определения

**Уязвимость** — свойство или дефект информационной системы (ПО, аппаратуры, процедур, персонала), который может быть использован для реализации угрозы и нарушения безопасности (конфиденциальности, целостности, доступности — триада CIA).

**Угроза** — потенциальная возможность нарушения безопасности; **атака** — попытка реализовать угрозу через конкретную уязвимость. **Риск** связывает вероятность угрозы, уязвимость и величину ущерба.

## Источники уязвимостей

1. **Программные** — ошибки проектирования и реализации (переполнение буфера, SQL-инъекция, XSS, небезопасная десериализация, слабая аутентификация).
2. **Аппаратные** — дефекты чипов, side-channel (Spectre/Meltdown), устаревшая прошивка.
3. **Конфигурационные** — открытые порты, дефолтные пароли, избыточные права, отключённое шифрование.
4. **Организационные и человеческий фактор** — слабые политики, социальная инженерия, утечки учётных данных.

## Классификация уязвимостей

| Подход | Примеры |
|--------|---------|
| По объекту | ОС, СУБД, сеть, веб-приложение, мобильная платформа |
| По происхождению | Проектные, реализационные, эксплуатационные |
| По эксплуатации | Локальная / удалённая; с аутентификацией / без |
| Стандарты | **CVE** (идентификатор), **CWE** (тип слабости), **CAPEC** (шаблон атаки) |

## Оценка: CVSS

**CVSS** (Common Vulnerability Scoring System) — числовая оценка критичности (базовая, временная, контекстная метрики). Уровни: низкий, средний, высокий, критический. Используется для приоритизации исправлений (patch management).

## Жизненный цикл

Обнаружение → регистрация (CVE) → анализ → разработка патча → тестирование → развёртывание → верификация закрытия. **Zero-day** — уязвимость без известного исправления на момент атаки.

## Связь с защитой

Устранение уязвимостей (патчи, hardening, сегментация сети, принцип наименьших привилегий) снижает поверхность атаки. Уязвимость сама по себе не равна инциденту — нужны угроза и возможность эксплуатации.
